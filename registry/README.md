# tests/registry/ — the regression ledger

This directory holds the **regression ledger**: one file per invariant, `RL-<slug>.md`, with
YAML frontmatter. Full spec and rationale — [`../docs/regression-ledger.md`](../docs/regression-ledger.md).

**What it is:** memory of "X was built here; a future change must not break Y, because Z; the
guard is this test." Not a duplicate of git history, not a diary — it's *why-it-is* +
*what-not-to-break* + a link to the guard test.

**Record ↔ test link (grep tag, not markdown parsing):** the guard test's name or a comment
contains `ledger:RL-<slug>`; the record's `guard.ref` holds the same id. `ledger-check.sh`
greps for those tags and reports OK / UNCOVERED / ORPHAN. Presence is proven by grep;
**greenness is proven only by a run** (`/e2e-full`) — so reconciliation is meaningful only
*after* a fresh run.

Files here:
- `_TEMPLATE.md` — copy it for a new record.
- `RL-example-checkout-total.md` — a worked example; delete once you have real records.
- `INDEX.md` — GENERATED by `ledger-check.sh`, gitignored, a snapshot of the last
  reconciliation. Never hand-edit; never commit.

**IDs are slugs, not counters** (`RL-checkout-total`, not `RL-042`) so two parallel branches
don't grab the same number and collide on merge. **Granularity is one invariant / risk zone,
not one commit** — group related regressions of an area under a single record with history.
